# LabLink — Architecture Decisions Log

This document records architectural decisions made for LabLink. When requirements were ambiguous or had multiple implementation paths, the simplest and most secure option was chosen.

| Decision ID | Context & Decision | Rationale |
|---|---|---|
| **DEC-001** | **Strict Pure Domain Layer**: All domain functions (`src/domain/`) are pure functions with zero I/O, zero network, zero React/Next.js/Supabase imports. | Ensures 100% deterministic testability in Vitest without mocking complex external SDKs. |
| **DEC-002** | **Postgres-Level Exclusion Constraint**: Overlapping approved bookings are prevented by `EXCLUDE USING GIST (equipment_id WITH =, time_range WITH &&)` on the `bookings` table. | Application-level locking is vulnerable to race conditions; the database kernel guarantees double bookings are physically impossible. |
| **DEC-003** | **No Direct INSERT Policy on `booking_requests`**: Students cannot insert directly into `booking_requests` via RLS; all submissions must call `submit_booking_request` RPC. | Eliminates race conditions in student pending request counts and guarantees initial status is always `pending`. |
| **DEC-004** | **Advisory Lock on Request Submission**: `submit_booking_request` acquires `pg_advisory_xact_lock(hashtext((SELECT auth.uid())::text))` before checking pending counts. | Eliminates concurrency holes where simultaneous requests from the same user could exceed `MAX_PENDING_REQUESTS_PER_STUDENT = 3`. |
| **DEC-005** | **Zero Service-Role Key in Production**: The deployed Vercel application uses strictly `NEXT_PUBLIC_SUPABASE_ANON_KEY` and user sessions; `SUPABASE_SERVICE_ROLE_KEY` is restricted to local seeds. | Prevents high-privilege credentials from ever being leaked or compromised in serverless execution environments. |
| **DEC-006** | **Fixed Search Path on SECURITY DEFINER RPCs**: All security definer functions set `search_path = public, pg_temp`. | Prevents search-path hijacking attacks in Postgres functions. |
| **DEC-007** | **Deterministic Equipment Fit (H7) over Fuzzy Search**: Removed fuzzy keyword matching from soft scoring; made category and spec matching a strict hard constraint H7. | Guarantees transparent, predictable score breakdowns and allows deterministic cross-department alternative equipment discovery. |
| **DEC-008** | **Campus Timezone Standard**: Single canonical constant `CAMPUS_TIMEZONE = 'Asia/Kolkata'` in `src/lib/constants.ts`; all database storage in UTC. | Avoids timezone conversion drift while keeping UI presentation localized to campus operations without DST variance. |
| **DEC-009** | **Soft Scoring Weights**: `Urgency: 0.35`, `Wait Time: 0.35`, `Past Fairness: 0.30` (sum to 1.0). | Balances deadline sensitivity with queue justice and equitable access for new/infrequent equipment users. |
| **DEC-010** | **Untrusted AI Output Model**: Gemini (`@google/genai`) extracts structured JSON on the server; returned data is treated as untrusted client prefill requiring user review and confirmation. | Completely insulates the platform from prompt injection, AI hallucination, and malformed database inserts. |
| **DEC-011** | **Anonymized Availability RPC**: Students query busy time ranges through `get_equipment_busy_ranges()` which returns only timestamps without user identities or project data. | Protects student research privacy and complies with FERPA-like data protection principles. |
| **DEC-012** | **Vitest Scenario Testing over Playwright**: Replaced heavyweight browser automation with isolated Vitest domain scenario tests. | Enables ultra-fast CI test runs (<2s) with zero flaky browser dependencies and zero secrets in GitHub Actions. |
| **DEC-013** | **No Demo Admin Credentials**: Synthetic accounts in seed data are restricted to students and faculty only (`faculty.*@lablink.demo`, `student*@lablink.demo`). | Prevents public demo accounts from holding administrative privileges over campus resources. |
| **DEC-014** | **Lean Standard Library Date Handling**: Replaced external date libraries (`moment`, `dayjs`, `date-fns`, `Temporal`) with standard `Intl.DateTimeFormat`. | Eliminates bloat and ensures minimal runtime dependency footprint. |
